# 万象灾厄 · Myriad Calamity

Minecraft **1.21.1** · NeoForge **21.1.233 或更高的 21.1.x** · Java **21**。无需 GeckoLib 或其他前置模组。

当前版本 **0.6.0**：机枢舞者双人 Boss、自然生成的机枢舞厅、消耗钥匙的中央核心、Blockbench 收臂持刃模型、厚重外展尾甲、流畅腿部动画、地面几何预警、阶段限伤、共舞弹射物与四阶段战斗曲。

## 安装和召唤

将 `build/libs/myriad_calamity-0.6.0+mc1.21.1.jar` 放入客户端和服务器的 `mods` 文件夹，替换旧版本。

1. 在主世界的新区块寻找“机枢舞厅”：直径约 41 格的深板岩与铜质舞台，带环形镶嵌、八根灯柱和中央发光核心。可生成于平原、向日葵平原、森林、桦木林、针叶林、热带草原或草甸中的平缓地形。
2. 持“机枢发条钥匙”右键正中央的 **机枢舞台核心**。
3. 两名舞者都生成成功后消耗 **1 把钥匙**（创造模式亦消耗）；空手、普通地面、和平难度、站位受阻、印记损坏或战斗未结束时不会消耗钥匙。
4. 创造模式和旁观者不会被攻击；切换生存模式体验战斗。

核心左右各 4 格为两名舞者的生成位置，需要坚实地面和 4 格净空。舞台上八枚磁石共鸣印记需要保持完整。核心无法被生存模式挖走。最后一名舞者被击败后，可再次消耗钥匙召唤。

配置文件位于服务器的 `config/myriad_calamity-common.toml`。`bossHealth` 控制新召唤舞者的共享生命池上限，`bossDamage` 以默认 9 点为基准等比例调整冲刺、下砸、共舞、阵列和剑光伤害；修改后重新召唤 Boss 才会使用新的生命值。

管理员可使用：

```mcfunction
/locate structure myriad_calamity:cogwork_theatre
/place structure myriad_calamity:cogwork_theatre
/give @s myriad_calamity:winding_key
```

`/place structure` 会实际放置舞台并改动场地。旧世界需要探索新生成区块才能遇到自然舞厅。刷怪蛋和 `/summon myriad_calamity:cogwork_dancer` 保留为创造/管理员调试入口，一次生成一对舞者。

钥匙可堆叠 16 个，合成配方：

```text
空   金锭        空
金锭 紫水晶碎片  金锭
空   红石粉      铜锭
```

## 双人共享生命值

两名舞者共同消耗 **480 点生命值**，显示一条血条。命中任何一名都会同步扣除共享血量。

| 阶段 | 共享血量 | 行为 |
| --- | --- | --- |
| 第一乐章 | 大于 66% | 轮换锁定冲刺、错位下砸、中心共舞、交织冲刺阵列 |
| 加速轮舞 | 33%～66% | 缩短前摇 |
| 错拍终曲 | 20%～33% | A 预警并攻击时 B 预警，随后 B 攻击、A 再次预警；下砸与冲刺可并行，双方每次都锁定玩家 |
| 孤独谢幕 | 20% 及以下 | **玩家最后成功攻击的舞者死亡，另一名保留剩余血量；保留正常冲刺与下砸，合舞尝试仅显示范围预警并失败** |

四阶段战斗曲按用户提供的原曲切片并编码为 OGG Vorbis，进入对应阶段后自动循环播放；阶段切换时立即换曲，附近没有存活舞者时停止。切片时长依次为 **76 秒、28 秒、56 秒、38 秒**。

双人期每次实际扣血最多 **48 点**，独舞期最多 **24 点**。共享血量到达 **66%、33%、20%** 时，该次伤害止于阶段阈值，立即进入 **3 秒转阶段免伤**，避免单次巨额攻击跳过阶段。此限制同时应用于最终生命值写入，护甲穿透不能绕过。

最终阶段不回满血：正常到达 20% 阈值时，玩家最后成功攻击的舞者死亡，幸存者保留 **96 点生命值**。只有实际扣血才更新最后攻击对象；玩家投射物也计入，环境伤害沿用最近玩家命中记录，多人共用同一记录。管理员 `/kill` 保留直接清理用途。

配对、血量、阶段、最后命中对象、锁定角色轮次、转阶段剩余免伤时间及舞厅占用锁均持久化。舞伴区块暂未加载时暂停双人战斗和受伤；舞厅不会因区块卸载或第一次退场而重复接受钥匙。重新加载后重新等待攻击前摇。

## 攻击和躲避

- **长距离冲刺**：主轨迹穿越约 **29 格**，准备时直接传送到起点并锁定玩家位置，随后高速保持直线；第三阶段在“冲刺+下砸、下砸+冲刺、双冲刺、双下砸”之间轮换，所有组合都沿 A 立即预警、B 延迟预警、双方排队的冲刺逻辑执行。第二只舞者在自身预警开始时重新读取玩家当前位置，不复用第一只的旧范围。橙红色地面几何预警标记整条轨迹及宽度。
- **错位下砸**：使用独立的轮换计数，主落点锁定玩家，副落点相隔 **5 格**，两者均提前预警；第三、第四阶段的每次下砸都锁定玩家，第二只舞者在自己的预警开始时重新读取玩家当前位置。第三阶段双下砸也沿同一套冲刺排队逻辑执行，不插入额外脚下预警。下砸只预警半径 **2 格** 的落点本体，随后产生最大半径 **8.5 格** 的地面扩散震波，以固定落点地面上方 **0.4 格** 判定；及时普通跳跃即可越过，震波不会跟随悬空的 Boss 升高。
- **共舞/独舞**：合舞使用半径在**10.85 格**范围预警，增加多层剑光效果，并最多发射 **6 波、每波 24 枚**向四周飞行的镰刃剑光；各波角度错开，镰刃外扩弧面朝向飞行方向。最终独舞保留正常冲刺与下砸；尝试合舞时只显示同样大小的范围预警，随后合舞失败，不造成合舞伤害，也不发射弹射物。
- **交织冲刺阵列**：起手就同时显示两名舞者的全部 **8 条** 预警路线（每名舞者 4 条，方向按轮次扰动）。准备 **1.8 秒**，随后在约 **3.4 秒** 内完成 **4 轮** 多方向高速冲刺；每条线路冲完即撤去提示；扫过后没有危险残痕，不显示安全区，也没有外围封锁。只在 Boss 实际穿越时判定伤害，结束后有 **0.6 秒** 收招。
- **独舞合舞失败**：幸存者尝试伸向缺席的舞伴，随后失衡垂落，没有伤害，是反击窗口。

战斗开始后，舞厅会显示半径 **16.5 格** 的橙红边界环和低透明边界墙，生存玩家被限制在环内；预警使用固定在地面的半透明橙红区域和明亮边框，不使用粒子。剑光及震波粒子仅用于攻击效果。

普通攻击每名舞者对同一玩家最多成功伤害一次；阶段三会按“舞者 A 预警→A 攻击并让 B 预警→B 攻击并让 A 再次预警”交错推进；下砸与冲刺可以在同一拍并行。整体出招间隔随阶段缩短，第二阶段会进一步加速。交织冲刺按轮次限制，每轮每名舞者最多一次，并遵循原版受伤间隔。Boss 不破坏方块；玩家建造的障碍会阻挡冲刺，攻击不会穿过障碍命中后方玩家。

最终幸存者掉落铜锭；玩家击杀额外获得 2 个机枢之心和“最后一支舞”进度。首次退场不掉落物品。

## 模型与动作

模型通过本机 **Blockbench MCP 1.6.1** 创建和导出，包含 **283 个方块、30 个棱角网格、35 组骨骼、2008 个渲染面**。保留 Minecraft 方块轮廓，手臂收拢到身前，增加厚手甲、握柄手指、加粗的臂腿装甲及方形靴；镰刀刃面放大并加厚。腿后尾甲增加内衬、叠层边、背脊和宽尾端，向两侧分开并分节向后翘起，避免单薄贴腿。金银两种配色，眼睛和核心常亮；攻击预警时显示折线光纹。

胸腰、腹节、颈冠、肩甲、肘腕、刀刃、膝踝及左右三节裙摆分别建骨，加入错拍回摆和攻击后的惯性收招。腿部增加交替屈膝、抬腿、换腿、蹬伸和落地缓冲，尾甲保留逐节滞后摆动。BB 工程保留可编辑的 **Catmull-Rom 曲线**，导出时按 **60 Hz** 烘焙，与 Blockbench 原生插值核对一致。游戏按攻击计时播放，并使用每个实体独立的姿势缓存平滑切换动作，保留完整的多圈旋转。

[可编辑 Blockbench 工程](modeling/cogwork_dancer.bbmodel) · [实际冲刺动画预览](modeling/previews/guard-dash-v4.gif) · [正面与尾甲预览](modeling/previews/tail-armour-v4.jpg)

14 组动画包括双人/独舞待机、冲刺蓄力与突进、下砸蓄力与冲击、共舞准备与旋转拥抱、阶段上弦、合舞失败、死亡，以及阵列准备、循环冲刺与最终收招。

## 构建和验证

```powershell
.\gradlew.bat build
python tools/validate_assets.py
```

当前通过编译、战斗规则与动画过渡检查以及资源/网格/动画/JAR 校验；已核对 Blockbench 原生曲线，检查实际模型与攻击姿势，并输出逐帧冲刺预览。**尚未启动 Minecraft 进行客户端、自然生成、专用服务器或多人战斗实测。**

`build` 的 `combatTest` 检查共享血量阶段、巨额伤害截停、转阶段存档恢复、最终退场对象、角色轮换、长冲刺、下砸间距、跳跃躲避、交织冲刺伤害时序、场地布局及召唤锁 NBT 保存/恢复。`animationTest` 检查二分采样、多圈旋转、最短角度过渡、中断动作与双实体隔离。两者均不启动游戏。

编辑 `.bbmodel` 后导出资源并构建：

```powershell
python tools/export_blockbench_assets.py
.\gradlew.bat build
```

通过本机 Blockbench MCP 完整重建模型源文件：

```powershell
python tools/rebuild_blockbench.py
python tools/validate_blockbench_curves.py
python tools/capture_blockbench_preview.py
```

这些 MCP 入口要求 Blockbench 服务运行于 `http://127.0.0.1:3000/bb-mcp`；重建脚本新建 BB 项目并更新 `modeling/cogwork_dancer.bbmodel`。`tools/generate_assets.py` 可重新生成物品、舞厅资源，并导入当前 BB 工程。

当前开发分支为 `mc-1.21.1`；`mc-1.20.1` 仅保存 Forge 模板基线，未移植本 Boss。原始 `demo/` 和 `demo1.21.1/` 模板保持不变。

角色参考来自《空洞骑士：丝之歌》机枢舞者及用户提供的图片，模型、贴图和动作由本项目制作，使用原版 Minecraft 音效，并为四个阶段加入独立的战斗曲循环。招式按 Minecraft 三维场地重新编排。角色及《空洞骑士：丝之歌》属于 Team Cherry，本项目为非官方同人模组。
