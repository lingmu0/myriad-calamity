# 万象灾厄 · Myriad Calamity

Minecraft **1.21.1** · NeoForge **21.1.233 或更高的 21.1.x** · Java **21**。无需 GeckoLib 或其他前置模组。

**0.11.1** 加入樱龙及云顶樱境。手持常樱之枝右键进入试炼，击败樱龙后可获得樱龙之泪。战斗曲在阶段切换和循环时平滑过渡。

**0.11.0** 全面升级双 Boss 的技能特效、模型与动作动画，并参考《黑神话：悟空》为杨戬三个阶段共新增 6 个变招技能（P1：腾跃裂地枪、云步虚晃变突刺；P2：雷斧变居合斩、掣电雷鞭变突枪；P3：天眼瞬闪神威斩、赤雷腾霄落枪，共 54 组骨骼动画）。重做杨戬冲刺、垫步、挥砍手部与脚下步法的全身动力学链协调性；通过 Blockbench MCP 重建机枢舞者 v2 发条螳螂模型（490 方块、双 1024×1024 金/银贴图），全面优化螳螂冲刺、下砸、速度驱动位移与四轮交织动作及战斗特效。

**0.10.8** 云台的天气随杨戬的转场动作渐变。召唤巨斧时乌云在约 4 秒内聚拢，雨量在 5 秒内升至小雨。天眼开启的 3.5 秒里，雨势渐强，蓝雷逐渐过渡为红雷。

**0.10.7** 恢复机枢舞者的圆形舞厅与原出招逻辑。关闭光影时沿用原来的特效外观，启用光影包时通过兼容渲染层绘制自定义特效，包括地震波、雷击、激光、蓄力、残影、天气和预警。

**0.10.5** 将预警、雷电、光柱和拖尾改用原版半透明发光渲染层。杨戬会随目标高度平滑抬头或低头，常规追踪的俯仰上限为 30°。

**0.10.4** 使用云海试炼专属的原版降水，二阶段入场小雨，三阶段雷暴。雷场改为依次落雷并绽放电弧，所有范围标记受同一个预警开关控制。重新制作杨戬的腿部与横扫动作，物品贴图统一为 16×16 像素。

**0.10.3** 给云海试炼二阶段加入乌云、间歇雷光和小雨，三阶段变为暴雨与频繁的红雷。雷电预警由外向内收缩，蓄光、激光、雷击以及武器和飞剑拖尾都使用了新的效果。

**0.10.0** 使用加高、加厚的杨戬模型。三阶段的 48 段动作已适配新骨架，挥枪轨迹跟随枪刃，天眼的蓄光与激光从额间发出。[查看动作预览](modeling/previews/yang_jian_v4_combat.png)

**0.9.5 的更新记录**

杨戬的手臂骨骼链按真人规则重做 —— 肘只有结构性携带角（左 +18°／右 −18°），姿势里原本写在前臂上的侧向倾角整体移到肩上，48 段动画全部落在携带角 ±1° 以内，挥击平面由肩产生；静止与持械姿态肩外展 18°、前臂内收 18°，手落在髋侧。P1→P2 转阶段的巨型雷斧改为**双手持握**（左手握在右手上方，双手间距 0.63~0.69 格，落砸时松开）。机枢舞者不再被方块阻挡，也不会互相推挤。云海试炼修掉了"死亡重生后第一次用登云符被吞掉、无法重新挑战"的问题。杨戬生命降至 75% 后升空召出巨型雷斧，挥舞整整一圈后砸出全场冲击，再依次释放两道地震波，两次攻击都可跳跃躲避。所有会转的技能统一**顺时针**；四连斩与六连斩在目标跑开时会变招为突刺或掷枪。雷斧召唤会赋予 3 层「雷斧残响」：之后每消耗一层，就把该招式**实际打出的整个范围**铺成一片蓝色雷电场（半径、扇形或车道与预警一致），场内有 14 格全高蓝色雷柱与地面电弧，站进去按间隔受闪电伤害、跳起可躲，并一直保留到下一次雷斧召唤。P2 五把飞剑环绕结束后剑尖持续指向玩家、逐把射出并可与其他技能并行。P3 技能池只保留细长的天眼激光与横向扫射激光，固定粗光柱已移除，神威天裁的两段剑雨改为三轮密集连发。三个阶段的快速垫步同时掷出飞刀。机枢舞者的预警去掉外描边、整体更淡，四个阶段的基础前摇统一压缩。保留黄色雷电激光、远距格挡与反弹、完整三阶段云海试炼，以及机枢舞者双人 Boss 战。

杨戬使用「登云符」右键进入挑战，指令为 `/give @s myriad_calamity:cloud_talisman`。四秒准备后开战，生命降至最大值 75% 进入 P2，降至 50% 播放天眼开启动画并进入 P3。防御条只负责吸收伤害和触发格挡，空条后仍可扣血，等待 2400 tick（两分钟）后回满；最终阶段生命耗尽才完成挑战，可用登云符或平台南侧磁石返回。入场生命保底默认是最大生命的 40%，可通过配置调整。人物保留已确认造型，共 48 套骨骼动画。追近改为半秒一段、最多前移 6 格的垫步，从第 0 tick 立即移动并同步投出无预警飞刀，收招时保持站位，沿途检查障碍与地面。[进入方式与 P1 玩法](docs/yang_jian_p1.md) · [P2 玩法](docs/yang_jian_p2.md) · [P3 技能、配置与验证](docs/yang_jian_p3.md) · [完整制作规格](docs/yang_jian_spec.md)

## 安装和召唤

将 `build/libs/myriad_calamity-0.11.1+mc1.21.1.jar` 放入客户端和服务器的 `mods` 文件夹，替换旧版本。

1. 在主世界的新区块寻找“机枢舞厅”：直径约 41 格的深板岩与铜质舞台，带环形镶嵌、八根灯柱和中央发光核心。可生成于平原、向日葵平原、森林、桦木林、针叶林、热带草原或草甸中的平缓地形。
2. 持“机枢发条钥匙”右键正中央的 **机枢舞台核心**。
3. 两名舞者都生成成功后消耗 **1 把钥匙**（创造模式亦消耗）；空手、普通地面、和平难度、站位受阻、印记损坏或战斗未结束时不会消耗钥匙。
4. 创造模式和旁观者不会被攻击；切换生存模式体验战斗。

核心左右各 4 格为两名舞者的生成位置，需要坚实地面和 4 格净空。舞台上八枚磁石共鸣印记需要保持完整。核心无法被生存模式挖走。最后一名舞者被击败后，可再次消耗钥匙召唤。

配置文件位于服务器的 `config/myriad_calamity-common.toml`，三个 Boss 各占一个区段。`[cogworkDancer]` 的 `health` 控制新召唤舞者的共享生命池上限，`damage` 以默认 9 点为基准等比例调整冲刺、下砸、共舞、阵列和剑光伤害；修改后重新召唤 Boss 才会使用新的生命值。杨戬的 `[yangJian]` 区段另有 `showAttackIndicators`（默认 `false`）。设为 `true` 显示攻击范围，包括转阶段下砸、雷电、剑雨和横扫。攻击动画、雷击、落剑和移动地震波始终可见。樱龙的 `[divineDragon]` 区段可配置生命值和基础伤害。

管理员可使用：

```mcfunction
/locate structure myriad_calamity:cogwork_theatre
/place structure myriad_calamity:cogwork_theatre
/give @s myriad_calamity:winding_key
```

`/place structure` 会实际放置舞台并改动场地。旧世界需要探索新生成区块才能遇到自然舞厅。0.10.6 期间已生成的方形舞厅会保留原地形，钥匙按圆形舞厅的共鸣印记布局校验。刷怪蛋和 `/summon myriad_calamity:cogwork_dancer` 保留为创造/管理员调试入口，一次生成一对舞者。

钥匙可堆叠 16 个，合成配方：

```text
空   金锭        空
金锭 紫水晶碎片  金锭
空   红石粉      铜锭
```

## 双人共享生命值

两名舞者共同消耗 **480 点生命值**，显示一条血条。命中任何一名都会同步扣除共享血量。

| 阶段 | 共享血量 | 行为 |
| --- | --- | --- |
| 第一乐章 | 大于 66% | 轮换锁定冲刺、错位下砸、中心共舞、交织冲刺阵列 |
| 加速轮舞 | 33%～66% | 缩短前摇 |
| 错拍终曲 | 20%～33% | A 预警并攻击时 B 预警，随后 B 攻击、A 再次预警；下砸与冲刺可并行，双方每次都锁定玩家 |
| 孤独谢幕 | 20% 及以下 | **玩家最后成功攻击的舞者死亡，另一名保留剩余血量；保留正常冲刺与下砸，合舞尝试仅显示范围预警并失败** |

四阶段战斗曲按用户提供的原曲切片并编码为 OGG Vorbis，进入对应阶段后自动循环播放；阶段切换时立即换曲，附近没有存活舞者时停止。切片时长依次为 **76 秒、28 秒、56 秒、38 秒**。

双人期每次实际扣血最多 **48 点**，独舞期最多 **24 点**。共享血量到达 **66%、33%、20%** 时，该次伤害止于阶段阈值，立即进入 **3 秒转阶段免伤**，避免单次巨额攻击跳过阶段。此限制同时应用于最终生命值写入，护甲穿透不能绕过。

最终阶段不回满血：正常到达 20% 阈值时，玩家最后成功攻击的舞者死亡，幸存者保留 **96 点生命值**。只有实际扣血才更新最后攻击对象；玩家投射物也计入，环境伤害沿用最近玩家命中记录，多人共用同一记录。管理员 `/kill` 保留直接清理用途。

配对、血量、阶段、最后命中对象、锁定角色轮次、转阶段剩余免伤时间及舞厅占用锁均持久化。舞伴区块暂未加载时暂停双人战斗和受伤；舞厅不会因区块卸载或第一次退场而重复接受钥匙。重新加载后重新等待攻击前摇。

## 攻击和躲避

- **长距离冲刺**沿圆形场地，从边缘发起。前两个阶段轮换锁定玩家的舞者，另一名从侧面穿场。第三阶段仍在混合冲刺、下砸和同类招式之间轮换，每名舞者在自己的预警开始时锁定当时的位置。
- **下砸**只预警半径 **2 格** 的落点。前两个阶段由一名舞者下砸、另一名舞者冲刺。下砸随后产生最大半径 **8.5 格** 的扩散地震波，跳起来可以躲避。
- **共舞与独舞**的范围预警半径为 **10.85 格**。共舞最多发射 **6 波、每波 24 枚**镰刃剑光。最终独舞保留冲刺与下砸，尝试合舞时显示相同范围的预警，随后播放合舞失败动作。
- **交织冲刺阵列**：起手就同时显示两名舞者的全部 **8 条** 预警路线（每名舞者 4 条，方向按轮次扰动）。准备时间取当前阶段的基础前摇（**28／18／15／35 tick**，即 1.4／0.9／0.75／1.75 秒），随后在约 **3.4 秒** 内完成 **4 轮** 多方向高速冲刺；每条线路冲完即撤去提示；扫过后没有危险残痕，不显示安全区，也没有外围封锁。只在 Boss 实际穿越时判定伤害，结束后有 **0.6 秒** 收招。
- **独舞合舞失败**：幸存者尝试伸向缺席的舞伴，随后失衡垂落，没有伤害，是反击窗口。

战斗开始后，舞厅会显示半径 **16.5 格** 的橙红边界环和低透明边界墙，生存玩家被限制在环内；预警使用固定在地面的半透明橙红区域，整体颜色偏淡且**不再描外边框**，不使用粒子。剑光及震波粒子仅用于攻击效果。

普通攻击每名舞者对同一玩家最多成功伤害一次；阶段三会按“舞者 A 预警→A 攻击并让 B 预警→B 攻击并让 A 再次预警”交错推进；下砸与冲刺可以在同一拍并行。整体出招间隔随阶段缩短，最终阶段进一步减少冷却和收招停顿。0.9.4 起四阶段的基础前摇由 34／24／18／52 tick 统一压缩到 **28／18／15／35 tick**，其中二阶段由 20 tick 减到 18 tick、四阶段由 44 tick 减到 35 tick；交织冲刺阵列不再使用单独的准备时间，直接取当前阶段的基础前摇。交织冲刺按轮次限制，每轮每名舞者最多一次，并遵循原版受伤间隔。舞者冲刺时穿过方块，不破坏方块。命中仍会检查视线。

最终幸存者掉落铜锭；玩家击杀额外获得 2 个机枢之心和“最后一支舞”进度。首次退场不掉落物品。

## 模型与动作

模型通过本机 **Blockbench MCP 1.6.1** 创建和导出，包含 **283 个方块、30 个棱角网格、35 组骨骼、2008 个渲染面**。保留 Minecraft 方块轮廓，手臂收拢到身前，增加厚手甲、握柄手指、加粗的臂腿装甲及方形靴；镰刀刃面放大并加厚。腿后尾甲增加内衬、叠层边、背脊和宽尾端，向两侧分开并分节向后翘起，避免单薄贴腿。金银两种配色，眼睛和核心常亮；攻击预警时显示折线光纹。

胸腰、腹节、颈冠、肩甲、肘腕、刀刃、膝踝及左右三节裙摆分别建骨，加入错拍回摆和攻击后的惯性收招。腿部增加交替屈膝、抬腿、换腿、蹬伸和落地缓冲，尾甲保留逐节滞后摆动。BB 工程保留可编辑的 **Catmull-Rom 曲线**，导出时按 **60 Hz** 烘焙，与 Blockbench 原生插值核对一致。游戏按攻击计时播放，并使用每个实体独立的姿势缓存平滑切换动作，保留完整的多圈旋转。

[可编辑 Blockbench 工程](modeling/cogwork_dancer.bbmodel) · [实际冲刺动画预览](modeling/previews/guard-dash-v4.gif) · [正面与尾甲预览](modeling/previews/tail-armour-v4.jpg)

14 组动画包括双人/独舞待机、冲刺蓄力与突进、下砸蓄力与冲击、共舞准备与旋转拥抱、阶段上弦、合舞失败、死亡，以及阵列准备、循环冲刺与最终收招。

## 构建和验证

```powershell
.\gradlew.bat build
python tools/validate_assets.py
```

当前通过编译、战斗规则与动画过渡检查以及资源/网格/动画/JAR 校验；已核对 Blockbench 原生曲线，检查实际模型与攻击姿势，并输出逐帧冲刺预览。**尚未启动 Minecraft 进行客户端、自然生成、专用服务器或多人战斗实测。**

`build` 的 `combatTest` 检查共享血量阶段、巨额伤害截停、转阶段存档恢复、最终退场对象、角色轮换、圆形场地、长冲刺、下砸间距、跳跃躲避、交织冲刺伤害时序、场地布局及召唤锁 NBT 保存/恢复。`animationTest` 检查二分采样、多圈旋转、最短角度过渡、中断动作与双实体隔离。两者均不启动游戏。

编辑 `.bbmodel` 后导出资源并构建：

```powershell
python tools/export_blockbench_assets.py
.\gradlew.bat build
```

通过本机 Blockbench MCP 完整重建模型源文件：

```powershell
python tools/rebuild_blockbench.py
python tools/validate_blockbench_curves.py
python tools/capture_blockbench_preview.py
```

这些 MCP 入口要求 Blockbench 服务运行于 `http://127.0.0.1:3000/bb-mcp`；重建脚本新建 BB 项目并更新 `modeling/cogwork_dancer.bbmodel`。`tools/generate_assets.py` 可重新生成物品、舞厅资源，并导入当前 BB 工程。

当前开发分支为 `mc-1.21.1`；`mc-1.20.1` 仅保存 Forge 模板基线，未移植本 Boss。原始 `demo/` 和 `demo1.21.1/` 模板保持不变。

角色参考来自《空洞骑士：丝之歌》机枢舞者及用户提供的图片，模型、贴图和动作由本项目制作，使用原版 Minecraft 音效，并为四个阶段加入独立的战斗曲循环。招式按 Minecraft 三维场地重新编排。角色及《空洞骑士：丝之歌》属于 Team Cherry，本项目为非官方同人模组。
